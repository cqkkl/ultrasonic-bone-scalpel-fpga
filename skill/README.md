# FPGA控制工程审查技能包

本技能包将本项目中遇到的工程问题整理为可复用流程，适用于FPGA/SoC采样与控制系统的源码审查、软硬件接口核对及参赛材料整理。它不依赖超声骨刀、Zynq-7020或特定控制器参数，可用于其他具有传感反馈与执行接口的控制工程。

## 包含内容

| 文件 | 用途 |
| --- | --- |
| [fpga-control-audit/SKILL.md](fpga-control-audit/SKILL.md) | 给编码助手使用的技能入口与执行边界 |
| [提示词模板](fpga-control-audit/references/prompts.md) | 工程清点、分环审查与证据归档模板 |
| [问题定位清单](fpga-control-audit/references/troubleshooting.md) | 触发条件、检查位置及验证方法 |
| [只读检查脚本](fpga-control-audit/scripts/audit_project.py) | 检查文件清单、来源哈希与复现材料是否齐全 |

## 使用方法

输入目标仓库、对应赛题要求、器件和工具版本；如需控制审查，再提供信号单位、控制周期、参数配置及测量记录。编码助手先阅读SKILL.md，按任务选择提示词与定位清单；脚本可独立使用，不需要模型或网络。

在仓库根目录运行，要求Python 3.9及以上，仅使用标准库：

```sh
python skill/fpga-control-audit/scripts/audit_project.py .
```

检查完整FPGA工程所需的HDL、约束、构建入口与验证数据：

```sh
python skill/fpga-control-audit/scripts/audit_project.py . --require-full-project
```

脚本将JSON结果输出到终端，默认不写入文件。基础模式只将来源清单不一致等问题判为失败，缺少完整工程材料记为提醒；严格模式将上述缺口判为失败。退出码0表示所选模式没有失败项，1表示有失败项，2表示参数或路径错误。**退出码0不代表代码正确、可综合、可运行或满足全部竞赛要求。**

复跑脚本的四项行为测试：

```sh
python skill/fpga-control-audit/scripts/test_audit.py
```

## 本项目中的提炼来源

1. 旧工程含绝对路径，而XSA/BIT不能替代完整源码，形成“先清点资产、后声明可复现”的检查项。
2. PID历史误差、模糊量化优先级和占空比单位问题，形成“状态更新与量纲核对”流程。
3. 多模块重复初始化GIC及GPIO结构体值传递，形成“共享外设生命周期”检查项。
4. FFT处理时钟与采样率混用，形成“采样序列与计算时钟分离”检查项。
5. 报告中双环方案与上传代码快照不一致，形成“报告主张逐项关联源码、构建和测试”的证据表。

## 已验证结果

本包脚本在当前源码快照上执行，并对哈希不一致的临时样本进行测试。检查结果与边界记录在[验证状态](../report/validation_status.md)。脚本可以发现缺少HDL、XDC、构建脚本和实测数据的材料缺口；它不能判定控制性能，亦未通过本次工作完成交叉编译或上板试验。

## 适用与失效边界

- 工程采用其他目录结构时，脚本的文件扩展名检查仍可使用，但可能遗漏不常见约束或构建格式，需人工解释。
- 控制器阶次、执行输入或单位改变后，重新确认模型和参数，不迁移本项目的数值。
- 文本中出现函数名只能作为源码线索，不能证明它已进入控制循环。
- 仿真结果、历史固件与当前源码分别记录；没有对应测试时不认定性能已验证。
- 本包是工程审查Skill，不是PYNQ专用Skill，也不包含已验证的自动硬件部署流程。

若在Codex中安装，可复制`fpga-control-audit`目录到本机技能目录；比赛审阅和独立执行脚本不需要安装。技能文件自身不授权修改外部仓库或操作硬件。
